# LocaleFlow AI：企业多语言运营平台

独立产品案例｜高级产品经理作品集

## 产品定位

LocaleFlow AI 管理企业内部从中文文案提交、英文主版本、多语言生成到发布的完整流程。平台同时接管拆单、排期、分配、提醒、容量平衡、延期预警和状态汇报，使员工只处理系统无法安全决定的异常。

产品可作为大型企业的内部系统，也可作为 B2B SaaS 部署给企业客户。每个客户的内容、人员、术语、翻译记忆、规则、Prompt 和指标相互隔离。产品不包含第三方语言供应商角色。

## 问题定义

企业本地化的主要瓶颈不只是翻译速度，而是端到端交付中的断点：

- 源文案缺少上下文或存在歧义，问题在多语言生成后才暴露；
- 机器翻译、LLM、术语库、翻译记忆和人工处理彼此割裂；
- 每种语言全量人工审核，无法把注意力集中在高风险内容；
- 项目经理依靠表格完成拆单、催办、调度和状态汇报；
- 人工修改缺少适用范围判断，特例可能错误污染全局知识；
- “翻译完成”与“可以发布”之间缺少明确的质量门槛和责任链路。

## 产品目标

1. 在生成前解决源文案问题，减少下游多语言返工。
2. 让低风险且通过检查的内容自动流转，只把异常交给员工。
3. 自动完成日常项目协调，同时保留可解释、可撤销的操作记录。
4. 将批准后的修改转化为有范围、有证据、可回滚的组织知识。
5. 同时管理质量、周期、人工触点和工作量，不以单一自动化率代替业务结果。

## 用户与权限

### 核心角色

- **Requester**：产品、运营、营销或内容团队；提交中文文案、上下文和发布要求，并处理源文案澄清。
- **Language Owner**：客户公司内部员工；负责某一语言的异常处理和最终语言确认。翻译与校对不拆成两个固定角色。
- **Platform Admin**：管理组织权限、工作流规则、语言资产和系统配置。

### 可选权限

法律、隐私、支付、定价或重大品牌内容可启用额外审批权限。它不是默认角色，只在客户配置的高风险策略命中时出现。同一员工可以同时拥有多项权限，避免为小型组织制造不必要的角色层级。

## 端到端工作流

`中文源文案 → Source QA → 英文主版本 → 多语言生成 → Locale QA → 人工异常 → 发布 → 知识更新`

### 1. 需求与 Source QA

需求方提交中文文案、使用场景、目标市场、上线时间、页面上下文、变量、字符限制、品牌语气和目标语言。

系统检查歧义、缺失上下文、数字、变量、术语冲突、敏感内容和可翻译性。无问题的低风险内容自动进入下一阶段；歧义、新术语或高风险问题返回需求方。源文案批准后冻结版本，后续修改触发影响分析。

### 2. 英文主版本

生成优先使用已批准的翻译记忆，并结合术语、禁用词、内容类型规则、页面上下文和 Prompt 版本。英文主版本通过检查并批准后，成为所有目标语言的可追踪参考；高风险内容同时保留中文原文。

### 3. 多语言生成与 QA

各 locale 并行生成，分别使用自己的术语、翻译记忆、语气、敬语、日期、数字、货币、变量和字符限制。检查通过的低风险内容自动流转；失败项进入对应 Language Owner 的异常队列。

### 4. 发布 Gate

发布前检查开放异常、必需审批、版本一致性、变量完整性、组件长度和发布包完整性。未通过时只阻断受影响的语言或内容，保留上一批准版本。

### 5. 知识更新

批准后的人工修改可以写入翻译记忆；术语、语言规则和 Prompt 调整先生成候选项。每个候选项必须显示证据、适用范围、冲突、影响面、试用结果和回滚路径。

## QA 设计

QA 不是发布前的一次校对，而是每次状态转换的准入条件：

| 环节        | 重点检查                                 | 失败处理                          |
| ----------- | ---------------------------------------- | --------------------------------- |
| Source QA   | 歧义、上下文、术语、数字、变量、可翻译性 | 返回 Requester                    |
| English QA  | 语义覆盖、术语、数字、品牌语气、格式     | 阻断片段或交给英语 Language Owner |
| Locale QA   | 目标语言规则、文化语境、长度、变量       | 交给对应 Language Owner           |
| Edit QA     | 人工修改引入的新错误                     | 阻止提交并说明原因                |
| Release QA  | 版本、审批、严重错误、发布包             | 阻止受影响范围发布                |
| Learning QA | 证据、适用范围、冲突和影响面             | 试用、人工批准或拒绝              |

AI 完成生成后，不设置另一个“AI 校对员”。系统使用确定性规则和独立质量信号检查输出；需要语言判断时再由 Language Owner 处理。

## 自动化与人工边界

### 系统自动完成

- 按语言和步骤拆分任务并倒排计划；
- 根据能力、容量、时区、历史质量和任务风险分配负责人；
- 跟踪依赖、提醒、阻塞和 SLA 风险；
- 在规则允许时重分配尚未开始的任务，并保留撤销入口；
- 生成状态摘要和工作量视图；
- 对低风险、检查通过的内容自动放行。

### 必须由员工决定

- 中文语义不明确或业务上下文缺失；
- 语言质量需要文化、品牌或专业判断；
- 全局术语或高影响规则的更新；
- 预算、质量门槛与上线时间发生冲突；
- 客户策略要求额外审批的高风险内容。

## 自进化知识机制

平台不会因一次人工修改直接更新全局术语库，而是先判断：

- 是否跨项目、内容类型和时间窗口重复出现；
- 是否有稳定的产品或业务定义；
- 多位 Language Owner 是否持续改成相同译法；
- 是否仅适用于某个市场、渠道、活动或创意语境；
- 是否与已有术语冲突；
- 更新后的影响范围和回滚成本。

知识作用域按具体程度覆盖：

`Global → Business Domain → Content Type → Locale → Project/Campaign → Segment Exception`

低风险且证据充分的候选可先小范围试用；品牌、产品、法律及覆盖既有规则的更新必须人工批准；局部创意表达自动保留为 Campaign Exception。系统监测人工修改率、规则冲突和发布后缺陷，表现恶化时回滚。

## 关键产品决策

| 决策                   | 原因                             | 代价与控制                                 |
| ---------------------- | -------------------------------- | ------------------------------------------ |
| 在全流程分布 QA        | 上游缺陷越早解决，受影响语言越少 | 规则配置更多；失败仅阻断相关片段和语言     |
| 采用批准后的英文主版本 | 建立跨语言共同参考和版本审计点   | 可能损失中文细节；高风险内容保留双语上下文 |
| 不设置独立 AI 校对角色 | 第二次生成不是独立质量证据       | 判断型问题仍由 Language Owner 负责         |
| 每种语言一个责任人     | 避免异常在审核池中失去所有权     | 需要容量监控和备份负责人                   |
| 知识更新先判断范围     | 防止活动特例污染共享资产         | 比自动写入更慢，但支持试用和回滚           |
| 自动化项目协调         | 减少拆单、催办和手工汇报         | 策略冲突仍升级给授权员工                   |

## 原型验证路径

Demo 使用一个新功能上线项目，包含中文 UI 文案、英文主版本以及日语、德语和法语输出。主入口 `Guided task` 让用户完成一条连续任务，而不是在多个模块间自行拼接流程：

1. 提交中文源文案及目标语言、组件上下文和上线要求；
2. 在生成前处理“关闭记录”的中文歧义；
3. 检查并锁定英文主版本 EN-v3；
4. 并行生成日语、德语和法语；
5. 处理日语敬语和德语字符超限，观察 Edit QA 重新运行；
6. 查看容量不足的判断依据，并确认尚未开始任务的重分配；
7. 通过 Release Gate，生成不连接外部系统的模拟多语言发布包；
8. 根据跨项目证据决定将术语候选设为全局术语、有限试用、活动特例或拒绝；
9. 查看本次模拟任务的执行汇总和自动化记录。

自由浏览工作台继续提供 Requests、Workflow、Multilingual Editor、Language Assets、Operations、Knowledge Updates、Analytics 和 Settings，用于进一步查看每个模块的详细状态与规则。

## 衡量框架

以下是后续验证指标，不是已取得结果：

- 请求到发布的周期中位数；
- 按内容风险和 locale 划分的人工触点率；
- 首轮 QA 失败率、返工率和发布后缺陷率；
- 异常处理时长、重分配率和 SLA 风险预测准确率；
- 知识候选采纳、复用、冲突和回滚率；
- 工作量预测误差及团队容量利用率。

## 证据边界

- **原型已实现**：从中文源文案到模拟发布的 Guided task、可点击工作流、本地状态变化、异常处理、运营调度、语言资产、知识决策、设置和演示分析。
- **产品方案已定义**：风险路由、范围化学习、可撤销自动化、工作量模型和治理策略。
- **后续路线**：生产连接器、持久化后端、SSO/RBAC、多租户隔离、模型评测和真实发布集成。
- **已测量结果**：无。Demo 中所有数字均来自种子数据，不代表客户使用或业务收益。
